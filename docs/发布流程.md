# Git 流程与桌面端发布指南

本文档面向接手本项目的开发者，说明两件事：

1. 日常改动怎么走 Git（分支、提交、合并）。
2. 怎么把项目打包成 macOS / Windows 安装包并发布到 GitHub Release。

---

## 一、仓库与分支

| 项 | 值 |
| --- | --- |
| 远程仓库 | `https://github.com/wokao2333/-.git` |
| 默认分支 | `main` |
| 开发分支 | `dev` |
| 历史遗留分支 | `backup-before-rewrite`（改写前备份，不要动） |
| 技术栈 | Vue 3 + Vite + Electron + electron-builder |
| 包管理器 | pnpm（CI 使用 pnpm 9 / Node 22） |

分支职责：

- `main`：稳定分支，只接受合并，不直接开发。
- `dev`：日常开发主线，功能开发完成后先合到 `dev`。
- 发布时在 `dev`（或已合入的 `main`）的提交上打 tag，CI 自动构建安装包。

---

## 二、日常开发 Git 流程

### 1. 开始新功能

```bash
git checkout dev
git pull origin dev
git checkout -b feat/your-feature    # 或 fix/xxx、chore/xxx
```

### 2. 开发并提交

```bash
git add -A
git commit -m "[Feat] (editor): 新增设备绑定模板功能"
git push -u origin feat/your-feature
```

提交信息规范（**必须遵守**）：

```
[Type] (scope): 简短中文描述

• 改动点一
• 改动点二
```

- `Type`：`[Feat]` / `[Fix]` / `[Chore]` / `[Docs]` / `[Style]` / `[Refactor]` / `[Test]` / `[Perf]`
- `scope`：英文小写模块名，如 `(editor)`、`(cockpit)`、`(electron)`、`(db)`
- 描述用简体中文，Header 与 Body 之间空一行，Body 用 `• ` 列表。

### 3. 合并回 dev

在 GitHub 上向 `dev` 提 PR，合并后删除功能分支：

```bash
git checkout dev
git pull origin dev
git branch -d feat/your-feature
```

> 向 `dev` / `main` 提 PR 时 CI 也会跑一次构建（`pull_request` 触发），
> 只验证能否打包，**不会**产生 Release。

## 三、发布桌面端（核心流程）

### 步骤 0：先改版本号（最容易漏的一步）

安装包文件名里的版本号取自 **`package.json` 的 `version` 字段**，与 Git tag **无关**。
当前 `package.json` 仍是 `0.3.1`，而 tag 已经到 `v2.0.28`，导致历史 Release 里的安装包
全部叫 `-0.3.1-arm64.dmg` / `Setup.0.3.1.exe`，用户无法区分版本。

发布前先改 `package.json`：

```json
{
  "version": "2.0.29"
}
```

让 `package.json` 的 `version` 与即将打的 tag（`v2.0.29`）保持一致。

### 步骤 1：确认代码已同步

```bash
git checkout dev
git status                  # 工作区干净
git pull origin dev
git log --oneline -5        # 确认要发布的提交在 HEAD
```

### 步骤 2：提交版本号改动并推送到 dev

```bash
git add package.json
git commit -m "[Chore] (release): 发布 v2.0.29"
git push origin dev
```

### 步骤 3：打 tag 并推送（CI 的唯一触发条件）

```bash
git tag v2.0.29
git push origin v2.0.29
```

> tag 必须以 `v` 开头，CI 的触发条件是 `tags: v*`。
> **推送 tag 即等于发布**，构建成功后会自动创建公开的 GitHub Release。

### 步骤 4：等待 CI 构建

打开 `Actions` → `Build Desktop Installers`，会并行跑三个 job：

| Job | 运行环境 | 产物 |
| --- | --- | --- |
| `build-mac` | `macos-latest`（arm64） | `.dmg`、`.zip`、`latest-mac.yml`、`.blockmap` |
| `build-win` | `windows-latest` | NSIS 安装包 `Setup.<version>.exe` |
| `release` | `ubuntu-latest` | 汇总上述产物，创建 Release |

`release` job 只有在 tag 触发时才运行（`if: startsWith(github.ref, 'refs/tags/v')`）。

### 步骤 5：验收

```bash
gh release view v2.0.29      # 或直接打开 Releases 页面
curl -s "https://api.github.com/repos/wokao2333/-/releases/latest" | grep browser_download_url
```

固定下载地址（README 中已引用）：
`https://github.com/wokao2333/-/releases/latest`

## 四、本地打包（不经过 CI）

本地打包**必须在目标系统上执行**：`better-sqlite3` 是原生模块，
在 macOS 上无法交叉编译 Windows 版本，反之亦然。

### 前置环境

- Node 22 与 pnpm 9（与 CI 保持一致，避免锁文件/原生模块差异）
- macOS：Xcode Command Line Tools（`xcode-select --install`）+ Python 3
- Windows：Visual Studio Build Tools（C++ 生成工具）+ Python 3

### 命令

```bash
pnpm install

# macOS：产出 dmg + zip 到 dist-electron/
pnpm run electron:build

# Windows：产出 NSIS exe 到 dist-electron/
pnpm run electron:build
```

`electron:build` 内部依次执行：

1. `pnpm run build-only` —— Vite 构建前端到 `dist/`
2. `pnpm run electron:rebuild` —— 用 `electron/rebuild.cjs` 针对 Electron 的 ABI
   与真实架构重新编译 `better-sqlite3`（自动识别 Apple Silicon 上的 x64/arm64）
3. `node electron/clean-build.cjs` —— 清空 `dist-electron/`
4. `electron-builder` —— 打出安装包

CI 中额外带 `--publish never`，因为发布动作交给 `release` job 用
`softprops/action-gh-release` 完成，不让 electron-builder 自己上传。

### 本地调试

```bash
pnpm run electron:dev       # 同时起 Vite(5173) 与 Electron，自动等待端口就绪
pnpm run electron:preview   # 先 build 再用 Electron 直接跑 dist/
```

## 五、产物说明

| 平台 | 文件 | 用途 |
| --- | --- | --- |
| macOS | `*.dmg` | 拖拽安装，用户主要下载这个 |
| macOS | `*-mac.zip` | 内置/静默更新用，配合 `latest-mac.yml` |
| macOS | `latest-mac.yml` + `*.blockmap` | 增量更新元数据 |
| Windows | `Setup.<version>.exe` | NSIS 安装向导 |

`package.json` 中 `build` 字段关键配置：

- `appId`: `com.wokao.app`，`productName`: `一次接线图`
- `directories.output`: `dist-electron`
- `asarUnpack`: `**/*.node`、`**/better-sqlite3/**`（原生模块不能进 asar）
- `extraMetadata.main`: `electron/main.cjs`（覆盖 `package.json` 的 `main`）
- mac target：`dmg` + `zip`；win target：`nsis`

## 六、已知坑与注意事项

1. **版本号不一致**：`package.json` 的 `version` 不跟着 tag 改，安装包文件名永远是同一个，
   用户无法分辨新旧包。发布前务必先改（见步骤 0）。

2. **产物文件名前缀丢失**：`productName` 是中文「一次接线图」，electron-builder 生成文件名时
   会过滤非 ASCII 字符，于是变成 `-0.3.1-arm64.dmg`、`Setup.0.3.1.exe`。
   如果想得到可读文件名，可在 `package.json` 的 `build` 中显式指定：

   ```json
   "artifactName": "maotu-${version}-${arch}.${ext}"
   ```

3. **macOS 只出了 arm64**：CI 跑在 arm64 的 `macos-latest` 上，Intel Mac 用户无法运行。
   需要兼容 x64 时，可在 `build` 中配置
   `"mac": { "target": [{ "target": "dmg", "arch": ["arm64", "x64"] }] }`，
   或本地执行 `npx electron-builder --mac --x64 --arm64`。

4. **未签名导致的安全拦截**（当前 `CSC_IDENTITY_AUTO_DISCOVERY: false`，属于预期行为）：

   - macOS 首次打开提示「无法验证开发者」或「已损坏」：
     右键 App → 打开；或执行
     `xattr -dr com.apple.quarantine "/Applications/一次接线图.app"`
   - Windows SmartScreen 提示：点「更多信息」→「仍要运行」。

   正式消除提示需要在仓库 Secrets 里配置
   `APPLE_ID` / `APPLE_APP_SPECIFIC_PASSWORD` / `APPLE_TEAM_ID`
   以及 Windows 代码签名证书，并取消 workflow 中对应的注释。

5. **`better-sqlite3` 架构不匹配**：报 `incompatible architecture` 时，
   重新执行 `pnpm run electron:rebuild`。该脚本通过 `lipo` 检测 Electron 二进制真实架构，
   避免在 Rosetta 环境下编译出错误架构的 `.node`。

6. **原生模块编译失败**：缺 Python 或 C++ 编译器。macOS 装 Xcode CLT，
   Windows 装 VS Build Tools（勾选「使用 C++ 的桌面开发」）。

7. **数据存放位置**：数据库在 `app.getPath('userData')/project.sqlite`
   （macOS: `~/Library/Application Support/一次接线图/`，Windows: `%APPDATA%\一次接线图\`）。
   升级安装不会覆盖该文件。

## 七、发布出错了怎么办

### 只重跑构建（不动 tag）

Actions 页面 → `Build Desktop Installers` → `Run workflow`。
这是 `workflow_dispatch`，只产出 Artifact，**不会**创建 Release。

### 需要重新发布同一个版本

```bash
# 1. 删远程 tag（会触发一次失败的构建，忽略即可）
git push origin :refs/tags/v2.0.29
git tag -d v2.0.29

# 2. 在 GitHub Releases 页面手动删除对应 Release（或 gh release delete v2.0.29）

# 3. 修好代码后重新打 tag
git tag v2.0.29
git push origin v2.0.29
```

> 已发布的 tag 不要直接复用，容易让用户下载到新旧混杂的包。
> 更稳妥的做法是升一个版本号（`v2.0.30`）重新发布。

## 八、发布前检查清单

- [ ] `package.json` 的 `version` 已改成与 tag 一致
- [ ] 代码已合入 `dev` 并 `git push` 完成
- [ ] 本地 `pnpm run build` 通过（含 `type-check`）
- [ ] 本地 `pnpm run electron:preview` 能正常打开主界面、数据库读写正常
- [ ] tag 名以 `v` 开头且未被使用过（`git tag -l`）
- [ ] 推送 tag 后 Actions 三个 job 全绿
- [ ] Release 页面能看到 dmg / exe，且文件名中的版本号正确
