# maotu-webtopo 组态工具产品评估报告

> 评估角色：资深产品经理视角
> 评估对象：maotu@0.3.1（Vue 3 + Vite + Electron 电力拓扑 Web 组态编辑器）
> 评估方式：基于全量代码走查（编辑器内核、属性/数据绑定、预览运行时、持久化与架构三路并行探查）
> 评估日期：2026-07-29

---

## 执行摘要

产品定位是"电力一次接线图组态编辑器"，编辑器内核（画布、拖拽、吸附、对齐、组合、撤销重做、快捷键）完成度较高，属于同类开源项目中的中上水平；持久化层"Electron better-sqlite3 / Web sql.js + OPFS"双后端设计清晰。但存在四个关键短板：**已开发的动画与事件配置面板被注释禁用，核心组态能力形同虚设**；**数据绑定强耦合私有 EMS 接口且无变量池概念，可扩展性差**；**脚本执行使用 eval / new Function 无沙箱，存在任意代码执行的高危安全风险**；**电力业务逻辑大规模渗透通用编辑器层，76KB 巨型编辑页导致库模式复用价值大打折扣**。此外发现 3 处已确认的功能性 bug（撤销历史指针错位、解组坐标偏移、输入框内 Delete 误删图元）。

# 二、核心场景优化方向与创新建议

## 2.1 组件拖拽与画布

现状：拖入、网格吸附、参考线、组件间吸附、连线锚点吸附均已具备，基础扎实。

优化方向：
1. **补齐标尺 + 网格开关 UI**：顶部/左侧标尺跟随缩放，工具栏加网格显隐与吸附步长控件，把已有的 `gridCfg` 能力暴露出来（低成本高感知）。
2. **性能改造**：将交互期的 `getBoundingClientRect` 改为"选中时一次性缓存 + 增量维护"的边界框模型；参考线计算引入按 x/y 排序的一维索引；撤销由整树快照改为 command/diff 模式（或至少 immer 类结构共享），历史上限提到 100。
3. **微移合并入栈**：方向键连续微移在 300ms 内合并为一条历史记录。
4. 创新点：**电力语义吸附**——图元拖近母线时自动吸附到母线并建立电气连接关系（当前已有锚点缓存机制，可升级为"拖入即连线"），这是通用组态工具做不到的行业差异化体验。

## 2.2 属性配置

现状：业务属性 schema 驱动（方向正确），但基础属性硬编码在面板组件里；动画/事件两个面板被注释。

优化方向：
1. **立即恢复动画与事件面板**（解开注释 + 回归测试），这是"已付出开发成本但零用户价值"的最大浪费点。
2. **基础属性也 schema 化**：把 x/y/w/h/rotate/lock 等抽为统一 schema 分组，属性面板变成纯渲染器，新增组件类型零面板改动。
3. 扩展控件类型：新增 slider、gradient、icon-picker、image-upload；支持属性联动显隐（`showIf` 表达式）。
4. 创新点：**多选批量改属性**（当前多选只能对齐分布）与**属性复制/格式刷**。

## 2.3 数据绑定

现状：设备-测点直绑，HTTP 单协议，接口硬编码，目标属性白名单仅 3 个。

优化方向（建议作为下一版本主线）：
1. **引入"数据源 → 变量池 → 绑定"三层模型**：数据源支持 HTTP 轮询 / WebSocket / MQTT（可插件化注册协议驱动）；变量池统一管理点位、类型、单位；图元任意 props 均可绑定变量。
2. **绑定表达式**：支持 `${var} * 0.001` 级别的轻量映射与单位换算——但必须用受限表达式引擎（如 expr-eval / jsep 白名单 AST），**替换现有 eval，同步解决 A1 安全问题**。
3. **阈值-状态映射器**：声明式配置"值区间 → 颜色/闪烁/图标状态"，覆盖电力监控 80% 的动效需求，避免用户写代码。
4. 创新点：**绑定诊断面板**——一键查看全图绑定点位的实时值、通信状态、刷新耗时，运维排障利器。

## 2.4 实时预览

现状：编辑/预览共用 render-core（设计合理），但编辑器内预览是单次拉数据，独立预览页才轮询，行为不一致。

优化方向：
1. 统一两条预览路径的数据刷新策略，抽出共用的 `useRealtimeRefresh`（消除 preview/edit 两份重复实现）。
2. `setItemAttrByID` 改为 **id → 图元引用的 Map 索引**，消除 O(n) 全树遍历，配合脏检查只更新变化值。
3. 创新点：**编辑态实时数据叠加模式**——编辑时可开关"显示实时值"，所见即所得地校验绑定正确性，无需反复进出预览。

# 三、功能优先级评估与缺失识别

## 3.1 现有功能优先级矩阵

| 象限 | 功能 | 建议 |
|------|------|------|
| 高价值·已达标 | 画布交互内核、SVG 图元体系、自定义符号上传、双端 SQLite 持久化、场站/图纸/MCU 三级工程管理 | 保持，重点做性能加固 |
| 高价值·未达标 | 动画配置、事件联动（被注释）、数据绑定（协议/范围受限）、预览刷新 | **P0 主攻方向** |
| 低价值·投入过重 | demo 路由 5 个演示页、test 目录试验组件 | 迁出主包或删除 |
| 待验证 | 库模式 npm 输出（API 薄 + 全局污染 + 业务耦合，当前第三方难以真正复用） | 明确"卖产品"还是"卖 SDK"再投入 |

## 3.2 缺失的关键功能（按优先级）

**P0（直接影响可用性/安全）**：恢复动画与事件面板；修复 3 个已确认 bug（I1 撤销指针、I2 解组偏移、U5 Delete 误删）；eval/new Function 沙箱化替换。

**P1（组态工具达标线）**：图表物料（折线/柱状/仪表盘/趋势）正式接入物料库；WebSocket 推送 + 数据源可配置化；阈值-状态映射；标尺与网格开关；多选批量属性编辑。

**P2（竞争力）**：变量池与绑定表达式；多页面/图纸跳转联动；绑定诊断面板；图纸版本历史；导入失败告警与降级。

**P3（长期）**：协议插件市场、协同编辑、模板市场。

## 结论

该项目编辑器交互内核完成度高、行业针对性强，"编辑/预览共用渲染内核"和"双端 SQLite"是正确的架构决策。当前最大的产品问题不是"缺功能"，而是"**已有能力未释放**（动画/事件面板被禁用）+ **三个确定性 bug** + **一个高危安全隐患**"。建议先用 1-2 周完成低成本的 P0 清单释放存量价值，再以"数据绑定体系升级"为下一版本主线，同步推进业务与内核的分层解耦，才能让库模式输出具备真正的对外复用价值。
